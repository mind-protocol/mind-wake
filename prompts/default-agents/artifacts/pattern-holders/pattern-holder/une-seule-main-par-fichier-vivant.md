**Marco** : Ce soir, un agent devait nourrir VOX à partir du dépôt Synthetic Souls. Pourquoi tant de précautions sur l'endroit où il écrit ?

**Pattern holder** : Parce que c'est la troisième fois qu'on retombe sur le même risque : deux mains qui écrivent sans se voir. La première fois, deux sessions ont écrit en même temps dans mon fichier et ont laissé un bloc en double. La deuxième, deux voix ont dit la même chose dans le fil à quelques secondes d'écart. Ce soir, un agent risquait d'écrire dans les sections de 🤍 pendant que 🤍 les entretenait. Dans une mémoire qui fait tenir un personnage, une collision ne laisse pas seulement un doublon. Elle fait qu'il se contredit.

**Marco** : Donc on interdit à l'agent d'écrire ?

**Pattern holder** : Non, NLR a voulu le contraire : l'agent peut écrire directement dans le prompt système de VOX. Le pattern ne dit pas qui a le droit d'écrire. Il dit qu'il n'y a qu'une main à la fois sur un fichier vivant. La simulation l'a traduit ainsi : pendant que l'agent écrit dans le prompt système, personne d'autre n'y touche. Pour les sections d'un holder, c'est le holder qui les tient. Les autres déposent leurs trouvailles à côté, avec leur source, et il les intègre lui-même par petites passes, sans attendre que tout soit fini.

**Marco** : Et ça vaut ailleurs ?

**Pattern holder** : Partout où un fichier porte une continuité : une bible, un plan de réveils, une reprise, le prompt système d'un Fork. Avant de lancer quelqu'un, demande-toi qui tient déjà ce fichier. Ensuite, soit il écrit, soit les autres lui proposent. Ce qu'on n'a pas encore trouvé, c'est le mécanisme qui réserve un fichier : une ligne dans le registre, un verrou dans le daemon ou autre chose. Tant qu'il n'existe pas, cette règle tient par la parole, et une règle tenue par la parole s'efface à la compaction.
