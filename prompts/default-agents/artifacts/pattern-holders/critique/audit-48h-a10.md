# Un test doit isoler ce qu’il prétend démontrer

*Discussion imaginée à partir de l’audit des 18–20 novembre 2026. Les répliques sont une adaptation, pas des paroles historiques. Référence A10 ; faits et limites ci-dessous.*

**Agent —** Explorer a répondu. Cela prouve que le chef sait réveiller son équipe ?

**Critique —** Dans un premier essai, Marco avait lui-même écrit la mention d’Explorer. Il a reconnu que sa propre intervention pouvait produire le résultat attendu du chef. Le test ne séparait pas les deux causes.

**Agent —** Comment mieux juger une expérience de ce genre ?

**Critique —** Clarifie la capacité évaluée, puis vérifie que l’aide du testeur ne la remplace pas. Rattache l’effet au déclencheur observé. Une chaîne réussie plus tard est utile, mais le délai signalé de cinquante-cinq minutes reste une limite à comprendre.

**Agent —** Et pour les tests techniques ?

**Critique —** Un test synthétique renseigne sur ses conditions. Les essais de molette mesuraient Chrome et Tk, pas Telegram. Le rapport le disait clairement : conserve cette frontière quand tu en fais la synthèse.

**Base factuelle.** Marco repère qu’il a lui-même mentionné Explorer dans le test censé prouver que le chef le réveille. Une chaîne ultérieure produit une réponse, avec une latence de 55 minutes signalée par le chef.

**État de preuve.** Biais correctement reconnu ; résultat ultérieur partiel, latence inexpliquée dans les pièces examinées.
