# Actualiser une critique avant de la transmettre

*Discussion imaginée à partir de l’audit des 18–20 novembre 2026. Les répliques sont une adaptation, pas des paroles historiques. Référence A03 ; faits et limites ci-dessous.*

**Agent —** J’ai signalé les trois corrections manquantes, puis l’auteur m’a dit qu’elles étaient déjà faites.

**Critique —** Dans ces échanges, vos versions se croisaient. Le chef a aussi reposé des questions auxquelles NLR avait répondu. Une remarque juste sur une ancienne version peut devenir inutile dans la version présente.

**Agent —** Comment rester utile quand plusieurs agents travaillent ensemble ?

**Critique —** Rattache ton jugement à ce que tu as effectivement lu : fichier, version ou moment. Avant de relancer, regarde si une réponse ou une nouvelle version change ton constat. Si tu ne peux pas le vérifier, exprime cette limite plutôt qu’un retard certain.

**Agent —** Et quand la correction est bien là ?

**Critique —** Tu peux fermer le point. Assurer le poste l’a fait après relecture du fichier. Moi aussi, je dois retirer une alerte dépassée sans en lancer une autre pour remplir mon tour.

**Base factuelle.** Le holder retire un reproche déjà dépassé ; plusieurs relectures se croisent avec des versions corrigées ; le chef reconnaît une revue en retard qui reposait des questions déjà traitées.

**État de preuve.** Défaut récurrent ; plusieurs corrections explicites et une relecture du fichier réussie.
