# src/adapters/claude

Adapter Claude Code (ADR-005), conforme à `src/contracts/adapter.ts`. Aucun appel modèle dans ce module ni dans ses tests : un faux exécutable (`test/fixtures/claude/fake-claude.ts`) rejoue des flux `stream-json`. **Aucune intégration réelle n'est démontrée** (voir « À tester en réel »).

## Modules

| Fichier             | Rôle                                                                                                                                                                            |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `claude-adapter.ts` | `ClaudeAdapter` : `probe`, `capabilities`, `start`, `events`, `cancel`, `reconcile`, plus `readQuota()` (jauge `/usage`, hors contrat).                                         |
| `command.ts`        | Arguments `claude -p` (session, jauge) et environnement explicite ; refus de tout nom de secret.                                                                                |
| `stream.ts`         | Parse pur des lignes `stream-json` (`SDKMessage`) ; ne conserve aucun texte du modèle, seulement noms d'outils, tailles et codes.                                               |
| `conversation.ts`   | UUID de session déterministe (clé + génération), stockage des conversations (port), fichier de prompt système nommé par son empreinte.                                          |
| `launch.ts`         | Ports : `ClaudeLauncher` (`sandboxClaudeLauncher` AppContainer, `hostClaudeLauncher` Job Object du runner) et `ClaudeNetworkPort` (relais fournisseur, **non implémenté ici**). |
| `quota.ts`          | `usage_report.rate_limits.limits` → `ProviderQuotaSnapshot` (`provider_quota_bp`, `measured`).                                                                                  |

### Conditions d'usage d'un abonnement (page « Legal and compliance »)

- Pro et Max relèvent des Consumer Terms ; l'usage est soumis à l'Usage Policy. Les limites annoncées supposent un usage **ordinaire et individuel** de Claude Code et de l'Agent SDK.
- La connexion OAuth est réservée aux titulaires d'un forfait, pour un usage ordinaire de Claude Code. Un tiers ne peut ni proposer la connexion claude.ai dans sa propre application, ni faire passer des requêtes par les identifiants d'un forfait pour le compte de ses utilisateurs, ni **collecter, stocker ou intermédier** des identifiants ou jetons claude.ai. La page ne restreint pas un utilisateur qui se connecte lui-même au binaire Claude Code non modifié avec son propre forfait.
- Aucun texte n'autorise ou n'interdit explicitement des sessions planifiées sans humain : la voie reste **expérimentale** (AGENTS §5). Conséquences pour Wake : l'humain se connecte lui-même par `/login` dans `CLAUDE_CONFIG_DIR` dédié ; Wake ne lit, ne copie ni ne relaie jamais ces identifiants ; le relais fournisseur ne doit pas détenir ni injecter de jeton claude.ai (au contraire de l'hypothèse « le broker détient seul le credential » valable pour une clé API) ; `account_on_hold` ou `billing_error` ferment la voie (code `fatal`) ; `credits_required` n'entraîne jamais d'achat.

## Comportement

- **Garde d'isolation.** `autonomy: "autonomous"` exige `launcher.isolation()` = `appcontainer` avec autotest de refus réussi (et sandbox opérationnelle), sinon `start` lève `ClaudeAdapterError("isolation_required")` sans rien lancer ; c'est le seul cas où `--dangerously-skip-permissions` est passé. `supervised` (lancement manuel) utilise `dontAsk` + `--allowedTools`. Un lanceur AppContainer sans `ClaudeNetworkPort` lève `transport_unavailable`.
- **Environnement.** `CLAUDE_CONFIG_DIR`, `DISABLE_AUTOUPDATER=1`, `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`, `HOME`/`USERPROFILE` et `CLAUDE_CODE_GIT_BASH_PATH` si fournis, variables de transport du relais. Tout nom de secret est refusé, y compris venant du relais. Les lanceurs n'héritent rien d'autre.
- **Racines.** Écriture : espace d'exploration (dossier de travail), dossier de configuration dédié, dossier personnel substitué. Lecture : dossier du binaire, dossier des prompts, racines supplémentaires (Git Bash).
- **Conversation.** Clé `conversationKeyFor(sessionId)` (défaut : la session). `--session-id` tant que le CLI n'a pas confirmé la session (`system/init`), puis `--resume`. Échec avant `init` : nouvelle génération, donc nouvel UUID, la continuité repassant par la mémoire Wake.
- **Événements.** `started` sur `init` ; `activity` (outils, tailles, nouvelles tentatives, refus d'outil, prompt modifié) ; `usage` mesuré au `result` ; `rate_limited` une fois, avec le délai jusqu'à `resetsAt` ; `error` (classement de `errorCodeFor`) ; `ended` (`result:<terminal_reason>` ou `stream_cut`). Après `result`, le processus est terminé (1 s) et le canal fermé.
- **Rapprochement.** `confirmed` seulement si le `result` a été lu et le processus terminé ; flux coupé, annulation, redémarrage : `uncertain`.

## À tester en réel (porte humaine : consomme le quota de l'utilisateur)

1. `claude.exe` (binaire natif) dans l'AppContainer : chargement, `LOCALAPPDATA` redirigé, `CLAUDE_CONFIG_DIR` et `HOME` substitués, Git Bash en lecture seule (`shell_tool_missing` sinon), argument vide `--tools ""` à travers le lanceur C#.
2. Transport : le conteneur ne joint que le pipe du broker ; il faut un relais qui expose ce pipe au CLI (proxy HTTPS ou `ANTHROPIC_BASE_URL`) **sans** détenir le jeton claude.ai. À concevoir avec `src/broker/`.
3. Connexion : `/login` par l'humain avec le même `CLAUDE_CONFIG_DIR` ; vérifier que le jeton porte `user:profile` (sinon pas de `usage_report`) et que `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` n'empêche pas `/usage`.
4. `/usage` en `-p` : présence réelle de `usage_report`, noms de `kind`, absence de requête modèle.
5. Cumul de `modelUsage` après `--resume` (différence supposée), unité de `resetsAt` et échelle de `utilization` dans `rate_limit_event`.
6. Forme exacte des erreurs : authentification absente, reprise d'une session inconnue, session déjà utilisée.
7. Délai de terminaison réel et consommation résiduelle après kill (`residualUsageBound` reste `null`).
8. Dépassement de la jauge après le seuil d'arrêt (ADR-004 : `overshootBoundBasisPoints` à mesurer).
