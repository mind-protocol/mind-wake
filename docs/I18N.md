# Desktop languages and default prompts

The desktop interface supports English and French. On first use it selects the first supported browser/system language, falling back to English. Settings → Language saves an explicit choice in `mind-wake.language` in the webview's local storage. Changing it reloads the main interface; the quick-input window updates its marked labels without discarding its draft. Native tray labels receive the same selection through a Tauri event.

`desktop/ui/i18n.ts` handles selection, formatting and interpolation. `translations.ts` contains the English catalog, with French source strings as stable keys and fallback text. Use `tr("French source text")` for interface strings and `tr("Projet : {0}", [projectTitle])` for parameters. Parameters are inserted in one pass and never translated. Dates and numbers use `formatLocale()`.

Static HTML uses `data-i18n` on the element containing the text, or `data-i18n-title`, `data-i18n-placeholder` and `data-i18n-aria-label` for attributes. Only explicitly marked app elements are translated. Keep conversation messages, document bodies, file names, user inputs and personal authorization content out of the catalog. Native menu labels live in the Rust desktop code and use `i18n::text`.

Built-in system, fork, second-chat, advice, planning, Steps and Bump/Bumpe instructions are in English, independently of the display language. Tool names, file paths, JSON keys and persisted enum values retain their existing contracts. Workspace-owned prompts and personalities remain user/agent content; this change does not rewrite them. Historical French Bump identification remains supported.

Run `npm run desktop:ui` and `npx vitest run desktop/ui` after changing translations. Existing UI tests pin French explicitly; `i18n.test.ts` also checks English, language selection and placeholder parity.
