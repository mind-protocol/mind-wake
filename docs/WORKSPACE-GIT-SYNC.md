# Workspace propre et synchronisation Git

Le panneau Réglages enregistre un dossier existant et une URL GitHub HTTPS ou SSH (`git@github.com:owner/repo.git`). Le protocole choisi est conservé ; origin doit correspondre exactement après normalisation du suffixe `.git`. Le dépôt doit déjà exister, avoir une branche nommée et un upstream explicite `origin/branche`. Wake ne clone pas, ne crée pas de dépôt distant et ne configure pas les identifiants. L'authentification et les clés hôte SSH doivent déjà fonctionner sans dialogue dans Git officiel.

Le dossier devient actif au prochain lancement du moteur, avant le probe du runtime et le calcul des racines. Les fichiers existants ne sont pas déplacés. Les nouveaux jobs, leurs scripts et leurs résultats utilisent ce dossier ; chaque job conserve son dossier d'origine, y compris les anciens jobs sans ce champ (ancien `workspace/`). Le fil est reconstruit à partir de l'archive du profil. La lecture de transcription Claude cherche dans le dossier du workspace actif ; les transcriptions restées sous l'ancien workspace ne sont pas migrées.

En mode Windows hôte consenti, le scheduler effectue cette maintenance indépendamment des conditions de réveil IA. Une policy active avec `hostUnsandboxedAcknowledged`, un profil autorisé et l'absence de Pause/Force-off sont vérifiés avant et pendant chaque cycle. Les profils isolés et simulés n'exécutent pas cette maintenance hôte. Aucun réveil IA ni débit fournisseur n'est nécessaire.

Première échéance : cinq minutes après la prise en compte des réglages. La prochaine échéance est persistée ; après succès ou erreur réseau temporaire, nouvelle tentative dans cinq minutes. `workspace-sync now` pose une demande au daemon, sans exécuter Git dans l'UI. Une divergence, un conflit, un push rejeté ou un workspace sale face à un remote avancé bloquent jusqu'à résolution locale et nouvelle demande. Aucun reset, rebase ou suppression de travail. Un crash laissant un verrou orphelin exige son inspection et retrait locaux avant reprise ; Wake ne vole pas un verrou par une suppression sujette aux courses.

Le cycle fetch → comparaison → pull FF-only si nécessaire → add/commit si nécessaire → push vise seulement la branche upstream. Le push utilise l'URL revue, ignore pushurl et neutralise mirror/followTags/récursion submodules, sans force. Les hooks Git locaux restent actifs ; `MIND_WAKE_AUTO_PUSH_RUNNING=1` évite le post-commit Wake récursif. Les fichiers ignorés restent ignorés. Ne placer dans ce dépôt que le contenu destiné à sa synchronisation : aucun déplacement ou filtrage de secrets n'est inventé par Wake.

Chaque commande Git est lancée sans shell dans un Job Object Windows possédé, avec askpass désactivé, GCM non interactif, SSH BatchMode et clés hôte strictes. Une commande est bornée à 30 secondes et le cycle à 90 secondes. Pause/Force-off/policy invalide annulent la commande et sa descendance ; la fermeture du moteur ferme aussi le job. Hors Windows, la primitive échoue explicitement. Les erreurs affichées excluent les sorties brutes Git et les identifiants.

CLI : `workspace-sync status`, `workspace-sync configure --workspace <dossier> --github-url <url> --enabled true|false`, `workspace-sync now`, avec les options habituelles du profil. Les changements de dossier demandent un redémarrage ; Sync now est désactivé avant chargement, pendant une opération, en cas de brouillon non enregistré, de sync désactivée ou de redémarrage en attente.

Validation de ce lot : tests Git/bare et Job Objects locaux, interactions DOM avec invoke simulé, compilation TypeScript/UI. La recette desktop packagée avec GitHub authentifié, arrêt depuis le vrai panneau et reprise après relance reste nécessaire avant acceptation et installation.
